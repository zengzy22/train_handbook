# Fitness Log Implementation Plan

> **For agentic workers:** Execute inline using executing-plans; the user has authorized development and private publication.

**Goal:** Build a private personal training journal whose complete data is readable by AI.

**Architecture:** Sites Vinext UI and route handlers share a user-scoped D1 repository and pure analytics functions. Native MCP reuses the same repository. JSON and CSV provide portable snapshots.

**Tech Stack:** React, TypeScript, Vinext, Cloudflare D1, Drizzle, Node test runner.

## Global Constraints

- No fabricated user records; Chinese UI; units and metric provenance visible.
- Private hosting and server-enforced user isolation on every data operation.
- Completed non-warmup volume only; heat/health values remain null when unknown.

## Verification examples

`node --experimental-strip-types --test tests/*.test.ts` must pass without network dependencies.

`curl -i http://localhost:5173/api/data` without a development sign-in cookie must return 401. Authenticated writes must reject invalid dates, non-finite/out-of-range values and incomplete sets with 400. Fetching data as a different user must not include another user's records. MCP tool results and JSON export must contain identical raw records.
