# 健身训练管理站点设计

状态：已实现并私有发布。入口：https://repnote-training-journal.tukututata.chatgpt.site

验证：TypeScript 校验、8 项领域测试、真实本地 D1 CRUD/跨用户隔离/MCP 集成测试、浏览器录入与刷新持久化、JSON 下载、手机无横向溢出、生产构建均已完成。线上私有登录门禁已确认，线上用户流程需用户在浏览器登录后使用。

## 目标与已知需求

为个人记录训练计划、每组实际重量与次数、体感质量，并用日历和趋势分析回顾训练。站点保存原始记录；Codex、ChatGPT 和其他 AI 能读取这些数据。

已读取原讨论中的用户消息。助手的产品说明与原型仅返回内容引用，无法核实其细节；以下为根据原始需求提出的实现方案。

## 方案与取舍

推荐使用私有 Sites、云端 D1 数据库与原生 MCP。它能支持多设备持久化，并由平台处理 ChatGPT 登录和站点访问权限。

备选：浏览器本地存储加文件导出，部署简单，但不能提供可靠的跨设备实时数据；独立服务加 OAuth，外部 AI 接入更灵活，但需另外管理部署、身份和凭据。

首版采用云端方案，同时提供完整数据导出。其他 AI 的实时接入需要支持私有 Sites 的平台服务凭据，不能把应用令牌当作绕过平台登录的手段。

## 页面与操作

1. **训练记录**：选择日期、训练类型和动作；逐组填写重量、次数、RPE、是否完成，记录训练时长、整体体感与备注。支持保存、修改和删除。
2. **训练计划**：创建和编辑计划模板，定义动作及目标组数、次数和重量；从模板开始一次训练，保留当次快照。
3. **训练日历**：按月查看训练日、选中日期查看原始记录；可补录历史训练。
4. **数据分析**：按时间范围查看训练频率、完成组数、训练容量、单动作力量趋势、热量和身体指标；数据不足时显示明确空状态。
5. **AI 与数据**：展示原生 MCP 连接方式、工具范围、JSON/CSV 导出及通用 AI 使用说明。

## 数据与指标

- 按站点用户 ID 隔离计划、训练、组记录和身体指标；不使用邮箱作为数据主键。
- 训练记录包含训练日期、状态、时长、热量及来源、备注、创建和更新时间。
- 每组保存动作、肌群、重量 kg、次数、RPE、完成状态及热身标记。
- 身体指标记录日期、体重、体脂率等可选值及来源；不自动获取 ChatGPT 或 Apple Health 数据。
- 容量为已完成非热身组的重量乘次数之和；不同动作的容量不代表相同生理刺激。
- 力量趋势使用同一动作的最佳组及估算 1RM，明确标记为估算，并显示适用范围。
- 热量优先使用用户或设备提供的值；估算值必须显示方法、输入与来源。缺少输入时保持为空。
- 空白新账户不植入虚构训练或健康数据。

## AI 读取与可移植性

提供只读工具：完整数据快照、按日期查询训练、获取计划、查询身体指标和计算训练摘要。所有工具复用站点的数据访问层，检查身份并返回单位、指标定义、时间范围及数据来源。

原生 `/mcp` 由 Sites 鉴权。工具只暴露当前用户的数据。初版避免 AI 写入训练，以减少误操作。

JSON 导出包含 schemaVersion、导出时间、时区、计划、训练、组记录和身体指标；CSV 按数据类别导出，保留关联 ID 和原始值。导出不包含密钥或平台凭据。

## 界面方向

采用中文、桌面侧栏与移动端底部导航。暖白背景、深石墨文字、克制的橙色强调，8px 间距系统，清晰表格与轻量图表。训练输入在手机上优先，分析在桌面上保持信息密度；提供加载、错误、空状态与保存反馈。

## 验收

验证计划到训练的完整流程、刷新后的持久化、日历回看、修改删除、指标计算和导出完整性。验证未登录拒绝访问、跨用户隔离、MCP 数据与页面一致。检查桌面和手机布局，再发布私有站点；未经实际调用不宣称外部 AI 已成功连接。
