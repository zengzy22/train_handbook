Repnote · 数据与部署关系图

代码可以复制到多个地方；生产用户数据只属于已部署 Site 的数据库。二者必须分开理解和备份。

不会因普通发布自动丢失

  • • 同一个 Site 发布新代码，数据库与代码版本分开保存
  • • 回滚代码不会自动回滚数据库或上传文件
  • • 换电脑、重建 Codex 任务工作区不影响生产 D1

会丢失或分离的情况

  • • 永久删除 Site：官方说明不可恢复
  • • 发布破坏性迁移：可能删表、删列或改坏记录
  • • 从同一仓库创建“新 Site”：推断会绑定新数据库，旧记录不会自动搬迁

当前最小备份方案

  • • 每次重要发布前，从「AI 与数据」导出完整 JSON
  • • JSON 保留原始关系与 ID；CSV 主要用于查看和分析
  • • GitHub 备份代码；导出的数据另存，不要提交到仓库

部署时要保持的身份

  • • 更新现有 Site，而不是新建一个同名 Site
  • • 保留 hosting.json 中的 project_id 与 DB 绑定
  • • 数据库迁移只做向前兼容，并先审查 SQL
